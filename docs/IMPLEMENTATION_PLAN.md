# План frontend Corpord

Дата: 2026-10-31. База: `origin/dev` (`d0c436c`). Backend: Go/Gin, PostgreSQL, Redis; frontend: Nuxt 4 (SPA), Vue 3, TypeScript, Pinia, Tailwind 4, reka-ui/shadcn. Сохраняем текущий стек, используем общий транспорт с cookie refresh и access token только в памяти.

## Архитектура и распределение

| Ветка                    | Ответственность                                                                                        |
| ------------------------ | ------------------------------------------------------------------------------------------------------ |
| `feat/frontend-api`      | DTO, типизированный API всех ресурсов, авторизация, ACL middleware, контрактные тесты, карта API       |
| `feat/frontend-admin`    | CRUD пользователей, автобусов, водителей, остановок, рейсов, связей рейс–остановка и трёх справочников |
| `feat/frontend-design`   | Публичные каталоги и карточки, auth и кабинет, адаптивная навигация, светлая/тёмная/системная тема     |
| `feat/complete-frontend` | Интеграция, AI логотип, конфигурация, PR CI, проверки и финальное ревью                                |

1. Сверить Swagger с актуальными handlers/models, включая завершающие `/`, неодинаковые ответы list/detail/create и legacy aliases пользователей.
2. Отделить API/DTO от страниц, централизовать обработку ошибок и восстановление сессии, ограничить admin маршруты.
3. Построить реальные публичные каталоги, поиск и страницы деталей; использовать серверные ID и реальные связи.
4. Реализовать admin CRUD с полями связей, проверкой дат/координат/цен, подтверждением удаления и состояниями загрузки/ошибок/пустого списка.
5. Обновить бренд, навигацию и токены темы. Системная тема отслеживает ОС; предпочтение хранится локально. Начальная тема применяется до отрисовки.
6. Интегрировать ветки, запустить typecheck, тесты, production build, браузерные сценарии; отдельный агент проводит ревью собранной ветки.
7. Исправить замечания, открыть PR в `dev`, дождаться CI. Merge оставлен владельцу. После merge GitHub Actions публикует GHCR `:dev`; локальный Compose обновляется отдельным pull/up.

## Границы API

В backend нет API бронирования/заказов, редактирования собственного профиля и изменения ролей. Интерфейс не изображает успешные операции для отсутствующих endpoint. OAuth callback обрабатывает backend; frontend начинает redirect flow и восстанавливает сессию на `/auth/callback`. Legacy `/users` совпадают по возможностям с `/admin/users` и не требуют дублирования экранов.
