Браузерные сценарии проверяют создание, свежий GET карточки, изменение и повторный GET для каждого ресурса; отдельно сохраняют и сверяют relation ID, даты и нулевые значения, пустой пароль при редактировании пользователя. Созданные записи ищутся по новым серверным ID, порядок списков не предполагается. После просмотра публичных каталогов/карточек записи удаляются в обратном порядке зависимостей.

Дополнительно проверены публичные страницы при ширине 390px без горизонтального переполнения, light/dark/system и изменение системной темы, регистрация через UI, профиль, восстановление сессии после reload, 403 обычному пользователю, завершение всех сессий и защищённый переход после logout.

E2E использует одноразовые контейнеры, сеть, БД, сгенерированные тестовые credentials и чистый dotenv. Реальные workspace `.env` не читаются, Nuxt/Nitro env не наследуются. Занятые порты отклоняются до запуска. Production frontend собирается с намеренно нерабочим API URL, затем запускается с корректным runtime override: успешный CRUD подтверждает конфигурацию сценария GHCR. Артефакты с тестовыми сессиями исключены из Git/Docker context. Cleanup выполняется также при SIGINT/SIGTERM.

Для итоговой проверки использован локальный образ `corpord-backend:frontend-role-test`: бинарник из чистой backend-ветки `3c8d93f` (локальный Go 1.27.3, CGO off) поверх существующего GHCR runtime с теми же миграциями. Это проверка приложения; исходный backend Dockerfile локально не пересобран, поскольку доступен legacy Docker builder без Buildx. GitHub Actions независимо проверил backend на Go из go.mod. Настоящая публикация GHCR произойдёт после merge.

## Исправлено по ревью и интеграционным проверкам

Независимое ревью: автор API проверил admin, автор admin проверил API/session lifecycle, публичные страницы, тему, harness и минимальный backend fix. Основной агент выполнил интеграцию и настоящие браузерные сценарии.

- Строковые параметры маршрутов преобразованы в валидные числовые ID.
- Исправлена семантическая контрастность primary/destructive в тёмной теме, в том числе shared UI и кнопка удаления.
- Запоздалые refresh/profile/logout не восстанавливают прежнего пользователя и не стирают новую сессию. Cookie mutation сериализована; навигация ожидает начатый login/register.
- Повтор после 401 сохраняет инициировавшую операцию identity: старая запись не исполняется под новым пользователем. Logout-all привязан к исходной сессии, включая preflight.
- Обновление форм обрабатывает числовые значения, которые Vue автоматически передаёт из number inputs; нули сохраняются. Добавлена регрессия.
- Убран вложенный main, исправлены старые compile ошибки native-select и Grafana stream, удалена неиспользуемая заглушка заказа.
- Исправлен backend read contract роли: опубликованный старый образ отдаёт пустую роль и блокирует административный UI. [Backend PR #13](https://github.com/SaRgEX98/corpord-backend/pull/13) должен быть смержен и собран прежде frontend.

## Зависимости и ограничения

Обновлён lockfile в допустимых диапазонах, Nuxt 4.6.3/Vue 3.5.44; Vue Router согласован с Nuxt 4.6 (`^5.4`), Zod обновлён до исправленной 4.x. Удалены неиспользуемые Google Fonts и vee-validate Zod/Nuxt adapters; UI-примитивы vee-validate сохранены. `vue-tsc` и Playwright добавлены как dev dependencies. Перед обновлением audit показывал 42 уязвимости (6 critical, 17 high); после — 14 (2 low, 12 moderate), **0 high/critical**. Оставшиеся transitive advisories требуют отдельной работы; `audit fix --force` не применялся. [Vue Router migration](https://router.vuejs.org/guide/migration/v4-to-v5.html), [Zod advisory](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5).

Node 26 выводит upstream deprecation module.register() при Nuxt prepare/typecheck/build; команды завершаются успешно. Полный интерактивный SSO Google/Yandex личными аккаунтами не выполнялся. Контракты и callback flow сохранены и покрыты тестами сессии. В API отсутствуют заказы/бронирования, self-edit профиля, выдача ролей, серверная пагинация; соответствующих фиктивных действий нет.

## Публикация

PR запускает typecheck, тесты и production build; образ не публикуется из PR. После merge backend PR #13 дождаться backend GHCR `:dev`; затем merge frontend PR и публикация frontend `:dev`. После обеих публикаций Compose обновляется отдельными pull/up из `corpord-infra`. Автоматический merge и обновление действующих контейнеров в эту задачу не входят. Наличие тестового образа локально не означает, что GHCR `:dev` обновлён.
