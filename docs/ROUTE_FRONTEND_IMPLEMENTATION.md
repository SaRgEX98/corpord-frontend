# Frontend поиска участков маршрута

Реализация этапов 1 и 4 плана. Требуется backend с контрактом
`docs/ROUTE_SEARCH_API.md` (backend PR), включая канонический
`GET /locations/:id`, города и effective_timezone остановок.
Сначала проверить и объединить зависимый backend PR; публикация и запуск — отдельно.

- shadcn Select/Reka Combobox используют цветовые токены; logout/all использует
  AlertDialog с фокусом на отмене, возвратом к триггеру и сохранением session guards.
- Города и остановки ранжируются сервером; внешние адреса Photon не становятся ID
  остановок. Пользователь явно уточняет город и выбирает обслуживаемую остановку.
- Поиск/пагинация/календарь/цена участка приходят с сервера. URL восстанавливается
  по каноническим ID; query названия не определяют точку поиска. Устаревшие ответы
  игнорируются при смене параметров. Карточка перепроверяет quote участка.
- Календарь на русском, Пн–Вс. В текущей Reka 2.x weekStartsOn — индекс относительно
  локали: для ru-RU Monday = 0; браузерный тест проверяет фактическую первую ячейку,
  а не только значение prop. Даты поиска определяются поясом отправления.
- День без рейсов недоступен; loading/error отличаются от no_trips. Тариф может
  быть null: показывается «Тариф уточняется». Места остаются unknown до интеграции
  реального источника; вместимость автобуса не используется как остаток.
- Администратор создаёт/редактирует города (пояс неизменяем после создания), связывает
  остановки с городом и при необходимости задаёт IANA override. Пустой город очищает
  связь (`city_id: 0`), пустой override наследует пояс города. Без известного пояса
  отправления сервер отклоняет поиск, UI предлагает выбрать другую точку.

## Собственная карта

Runtime переменные Nuxt (пустые по умолчанию):

```
NUXT_PUBLIC_MAP_STYLE_URL=https://maps.example.test/styles/light.json
NUXT_PUBLIC_MAP_DARK_STYLE_URL=https://maps.example.test/styles/dark.json
```

Значения в примере не являются рабочими адресами. Настройте свои style JSON,
источники PMTiles/тайлов, glyphs/sprites и CORS/Range согласно инфраструктурному
руководству. Frontend не содержит публичных OSM/Photon/Nominatim defaults.
MapLibre/PMTiles/CSS загружаются после «Показать карту». Переключение темы меняет
style, координаты и текст остаются доступны при ошибке карты. Протокол PMTiles
общий для нескольких экземпляров карты; поздняя загрузка после unmount не создаёт
карту. Атрибуция OSM видима. Показаны точки, дорожная траектория не рассчитывается.

## Проверки и ограничения

`npm run typecheck`, `npm test`, `npm run build`; focused browser fixture:
`CORPORD_E2E_BASE_URL=... npx playwright test tests/e2e/route-ui.spec.ts`.
Сценарий проверяет русский календарь/понедельник, цену в копейках, дату у полуночи,
canonical URL restore, подсказки, ошибку геосервиса и mobile/dark. Он использует
перехват API, а не подтверждает интеграцию реальных данных. Основной workspace E2E
обновлён под Select и AlertDialog. Реальное end-to-end ревью выполняется на отдельной
БД/аккаунтах после сборки согласованных веток.

Реальный региональный индекс Photon и подложка должны пройти пилот качества,
ресурсов, лицензий и обновлений перед активацией карты/геопоиска. Не реализованы
источник реальных остатков, бронирование, платежи и коэффициенты спроса; они требуют
отдельных согласованных правил и этапов 5–6.

Карту отдельно проверяет `tests/e2e/route-map.spec.ts`: запустить отдельный frontend
с URL стилей `/test-map/light.json` и `/test-map/dark.json`, затем задать
`CORPORD_E2E_MAP_STYLE_TEST=1`. Браузер подменяет оба style JSON локальными fixtures
без внешних источников, проверяет ленивый запрос, сохранение карты при сортировке,
переключение светлого/тёмного стиля и отсутствие запросов к публичным демосервисам.
Это проверка рендера MapLibre и интеграции стиля; настоящий PMTiles и региональный
индекс ею не проверяются.
