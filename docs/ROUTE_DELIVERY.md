## Границы первого этапа

Реализуется информационный поиск прямого рейса или его участка для одного
пассажира. Новые цены — целые копейки RUB; календарь, выдача и quote используют
одну серверную политику суммы тарифов соседних остановок. `base_price` остаётся
отдельной legacy-величиной и не добавляется повторно. Тариф может быть `null`,
если данные не подтверждены. Новая цена не означает бронь или гарантию места.

День поиска определяется подтверждённым IANA timezone отправления; прибытие —
своим поясом. Остановки сопоставляет администратор, адреса не разбираются для
автоматического назначения городов. Для старых остановок сопоставление — явное
условие включения нового поиска; прежние публичные endpoint сохранены.

OpenStreetMap/MapLibre и собственный Photon выбраны вместо обязательного платного
API. Публичные Nominatim, тайлы OSM и demo Photon не являются зависимостью.
Шаблоны находятся в Git backend `deploy/geo`, действующий `corpord-infra` не менялся.
Настройки: backend `PHOTON_BASE_URL`/`PHOTON_TIMEOUT`; frontend
`NUXT_PUBLIC_MAP_STYLE_URL`/`NUXT_PUBLIC_MAP_DARK_STYLE_URL`. По умолчанию внешние
сервисы не включены; поиск собственных остановок от них не зависит.

## Что остаётся следующим этапом

- Подготовить разрешённые региональные данные, реальный индекс Photon и архив
  карты со стилями, кириллицей, sprites и атрибуцией; выполнить пилот русских
  адресов/POI и ресурсные/нагрузочные замеры. Маленькая синтетическая smoke-фикстура
  подтверждает только механизмы импорта/запуска и UTF-8, не покрытие РФ.
- Подтвердить города/timezone существующих остановок на целевом окружении после
  резервного копирования и применения миграции; согласовать смысл старых дат.
- Выбрать достоверный источник мест (перевозчик или контур резервов/продаж).
  До этого статус мест — unknown; вместимость не используется как остаток.
- Утвердить политику сборов/тарифов и спроса. Надбавки, реальные резервы,
  платежи, сезонные правила и ML не включены в информационный этап.

Все изменения проходят PR в `dev`; пользовательские ветки и действующие данные
не перезаписываются. Merge и обновление действующих контейнеров требуют отдельного
шага после ревью. Runtime-геоданные и реальные `.env` в Git не включаются.
